# UniProxy 0.2.3

## 更新内容

- **修复订阅下载成功后误报 TLS 参数错误**：可选 TLS 已关闭时，类型正确的 `skip-cert-verify: false` 和空 SNI 仅是无操作默认字段，不再因此拒绝节点。保持原 TLS 开关、证书验证与节点身份；插件和 sing-box 同类字段采用同样的窄范围兼容。
- **扩展静态节点格式**：支持 Quantumult X、Surge／Surfboard、Loon 的本地节点段及 Base64 包装，包括带引号的逗号、等号、转义和 IPv6 端点。只提取节点，不采用全局规则、DNS、MITM 或脚本。
- **兼容 URI 订阅元数据**：允许列表开头一个有界 `STATUS=` 信息行，以及解码后完全相同的 SNI 别名；冲突别名、同名重复参数和非法主机名仍明确报错。
- **保留完整性与安全边界**：远程节点 provider、include、策略组 `policy-path` 等不会被静默遗漏或执行。不完整订阅不导入或清理旧节点，强制刷新也不绕过解析错误；不会删除中转依赖、猜测认证名或自动跳过证书验证。

## 兼容范围

- 静态客户端文本未显式声明 UDP 时，**按 TCP-only 导入**。不同客户端即使语法相同，默认值也可能不同；需要 UDP 时，源中须明确设置 `udp-relay=true` 或对应选项，界面已在所有导入模式提示。当前仍只允许回环 UDP 监听。
- 不保证完整复制各客户端的全局策略或默认行为。无法无歧义表达的 VMess AEAD、TLS SNI、WebSocket Host、SS 插件 Host 等需明确源字段，否则报错，不以猜测换取表面导入成功。
- SNI 含 `@` 等非法主机名继续拒绝，需订阅提供者修正；解析成功和 Mihomo 配置校验通过均不代表远端节点可连接。

## 升级与数据安全

1. **先退出旧 UniProxy 实例并确认其内核退出，再替换主程序**。沿用原数据目录、匹配主密钥和启动参数，不必重新导入已有数据。
2. **不要在运行中复制或覆盖数据库**；仅复制在线主库不是一致备份，不得混用不同数据库的 WAL/SHM。物理备份、迁移或恢复前，源与目标实例都须停止。
3. Mihomo 仍固定 v1.19.32，已有兼容内核无需重装。本版无数据库 schema 迁移，也不改变系统代理或防火墙；发布不会自动替换正在运行的程序。

## 验证

开发期隔离验收包括 Go 单元/集成与 vet、严格 TypeScript、36 项 UI 工具测试、37 项浏览器流程、解析器 fuzz、9 组合成格式的 Mihomo 配置校验，以及自有回环 TLS ClientHello 身份检查。原问题订阅 7/7 节点和其余 6 份有效样例各 12 节点通过离线解析及内核校验；另 2 份非法 SNI 样例按预期拒绝，原始链接与凭据未入库。

正式发布的 CI、资产摘要与 Windows x64 二进制验收见[发布记录](<https://github.com/FYHC1/uniproxy/blob/main/docs/release-0.2.3-verification.md>)。Linux/ARM64 交叉构建不等于目标机器实跑；Docker、race、公网节点连通和吞吐不在本次新增验收范围。
