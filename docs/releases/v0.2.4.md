# UniProxy 0.2.4

## 更新内容

- **编辑代理池弹窗更紧凑**：收紧字段间距、行高和提示块，常见窗口高度下可直接看到名称、策略、分组与节点区。
- **包含分组固定显示 4 行**：分组更多时在字段内滚动，不再把弹窗不断撑高；分组搜索、全选和滚动保持可用。
- **包含节点增加状态筛选、排序和延迟测试**：可按全部、已启用、已禁用、检测健康、检测异常、尚未检测筛选；可按名称、延迟、速度、最近更新排序。筛选、搜索和排序只影响显示，不会清除已选节点；“全选”作用于当前筛选结果。
- **延迟测试使用真实任务**：只提交已勾选、已启用且无中转错误的节点，并要求内核运行、当前配置已应用。按钮不会在前端伪造延迟或健康状态；后端仍执行任务互斥、节点数量和中转依赖校验。
- 保留即时勾选与原有组匹配、UDP 兼容、旧排除记录语义；保存仍由同一选择推导 `nodeIds/excludeNodeIds`。本版仅前端交互、样式与测试，无 API、数据库 schema、Mihomo 内核或安全策略变化。

## 兼容范围

- 无数据库 schema 迁移，不改变订阅解析、节点身份、中转依赖、策略组或系统代理/防火墙设置；Mihomo 仍固定 v1.19.32。
- 延迟测试必须在内核运行且当前配置已应用时使用；检测结果反映实际任务返回值，不代表远端节点长期可用或吞吐。
- 筛选和排序是显示层状态，不写入配置；隐藏的已选成员仍会在保存时保留。

## 升级与数据安全

1. **先退出旧 UniProxy 实例并确认其内核退出，再替换主程序**。沿用原数据目录、匹配主密钥和启动参数，不必重新导入已有数据。
2. **不要在运行中复制或覆盖数据库**；仅复制在线主库不是一致备份，不得混用不同数据库的 WAL/SHM。物理备份、迁移或恢复前，源与目标实例都须停止。
3. 本版无 schema 迁移；已有兼容内核无需重装。发布不会自动替换正在运行的程序，部署需单独执行。

## 验证

发布前复跑 39 项 UI 工具测试、40 项隔离浏览器流程、严格 TypeScript 和生产 Web 构建；Go 单元/集成测试与 vet 以本轮发布记录为准。浏览器覆盖状态筛选/排序仅显示、隐藏成员保留、真实检测请求体、禁用原因和四行滚动。正式发布的四平台构建、资产摘要与 Windows 程序验收见[发布记录](<https://github.com/FYHC1/uniproxy/blob/main/docs/release-0.2.4-verification.md>)。
