# UniProxy 0.2.2

## 更新内容

- **Windows 启动失败不再看不到错误**：双击无参数程序、使用独立交互控制台时，失败窗口会保留错误并等待 Enter；从已有 PowerShell/cmd、脚本或健康检查启动时不阻塞。
- **独立启动诊断日志**：报告构建版本、失败阶段，以及已成功解析的数据路径，单份最多 16 KiB；默认保存到用户缓存目录的 UniProxy/logs，无法写入时回退临时目录。终端会显示具体路径。不记录节点配置、主密钥、原始内核日志或无效命令参数。
- **Windows 自有子进程退出保护**：在内核版本探测、配置校验和运行前建立进程生命周期保护。UniProxy 正常退出或被强制结束时，其创建的内核子进程会随之退出，不扫描或终止其他实例。
- **更早响应退出**：慢启动期间也能接收退出信号并取消应用工作，减少关闭窗口后的残留风险。
- **数据库与重复启动诊断**：SQLite 损坏会给出保留数据、离线恢复的明确提示，不会自动清空数据库或切换到空库；先设置有界锁等待再初始化 WAL。管理端口占用时先报错，不先打开数据库。
- **保持自动化兼容**：CLI 参数语法错误仍返回退出码 2；健康检查失败保持非零退出和终端错误，不反复生成持久启动日志。

## 升级与数据安全

1. **先正常退出全部旧 UniProxy 实例并确认内核退出，再替换主程序**，沿用原数据目录与匹配主密钥。已有兼容 Mihomo 无需重装。
2. **禁止在运行中复制或覆盖数据库**，不能混用不同数据库的 WAL/SHM；仅复制在线主库不是一致备份。迁移或物理恢复前，源和目标实例都必须停止。
3. 本版不会自动修复已经损坏的数据库。若出现 malformed(11)，先保留数据库、匹配密钥和可能存在的 WAL/SHM，再从完整一致备份离线恢复；不要删除密钥或数据来绕过错误。
4. Windows 子进程保护只负责 UniProxy 自己创建的进程，不是常驻 Windows 服务或自动重启器，也无法阻止管理员在线覆盖数据库。

## 验证与边界

- 已有隔离验收覆盖 Go 单元/集成、真实本机 Mihomo、三轮强制结束后同目录重启、两轮真实控制台关闭后重启、错误窗口保留和日志、嵌套 Job/句柄继承及合成损坏库保护。
- 提供 Windows/Linux × amd64/arm64 构建；Windows x64 有实际运行验证，其他架构交叉构建不等于目标机器实跑。Linux 异常父进程退出保护、所有 Terminal/ConPTY 宿主、Docker 实机和 race 仍非本轮验收范围。
- Mihomo 保持 v1.19.32，不更改系统代理、防火墙、数据库 schema 或仅回环 UDP 等安全边界。发布不会自动升级正在使用的实例。
