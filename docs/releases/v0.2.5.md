# UniProxy 0.2.5

## 更新内容

### 全局出站网卡选择

- 设置页新增「03 全局出站网络」，可选择物理以太网、WLAN 等本机网卡作为内核出站源，或保持「自动（系统默认路由）」。用于绕开 Clash Verge 等程序 TUN 虚拟网卡接管默认路由、导致节点检测全部超时的环境问题。
- 保存前由服务端校验网卡存在、已启用且非回环，并拒绝首尾空白。固定内核不校验网卡名（`mihomo -t` 对不存在的网卡仍报成功），只会表现为误导性的拨号/DNS 失败，因此非法值在管理层直接拒绝。
- 新增只读 `GET /api/interfaces`，仅返回网卡名称、启用/回环标记与地址前缀，不返回网关、MAC 或 DNS 状态；设置页可刷新列表，已保存但当前不可用的网卡会被标注而不是静默改写。
- 节点级 `interface-name` 继续被拒绝：订阅和导入的节点不能自行选择源网卡或写入文件路径。绑定失效网卡时内核直接拨号失败，不会回退直连。

### Linux 实机稳定性修复

- 私有认证内核探针由单次 750ms 检查改为 3 秒有界重试（每次 1 秒、间隔 100ms），并对 `/proxies` 原生出站暴露检查增加同样的有界重试；超期仍失败并停止内核。认证与探针标准没有降低。
- Linux 版本探测、配置校验和正式启动统一调用 `PrepareCommand`，在内核子进程上设置 best-effort `Pdeathsig=SIGTERM`：主程序被 `kill -9` 后自有 Mihomo 随之退出，不再遗留监听。Windows 继续使用 Job 对象，其他平台为 no-op；这不是 Job 等价保证。

## 兼容范围

- 无数据库 schema 迁移，不改订阅解析、节点身份、中转依赖、策略组或系统代理/防火墙设置；Mihomo 仍固定 v1.19.32。
- 出站网卡设置只约束 UniProxy 自有内核的出站源网卡：它不创建虚拟网卡、不是 TUN、不修改系统路由表或 DNS，也不影响其他程序。系统级 TUN/VPN 仍可能按路由规则接管流量，若目标流量仍被其他程序的 TUN 转发，节点检测依然可能失败。
- Windows 网卡名对应「网络连接」/ `Get-NetAdapter` 的 Name 列（如 `以太网`、`WLAN`），区分大小写；网卡禁用或拔出后保存会被拒绝，运行中失效则直接拨号失败。
- Linux 的 `Pdeathsig` 是 best-effort：父进程被强杀时内核通常随之退出，但不含 Windows Job 对象那样的强保证；父线程迁移或平台限制时可能来不及清理。

## 升级与数据安全

1. **先退出旧 UniProxy 实例并确认其内核退出，再替换主程序**。沿用原数据目录、匹配主密钥和启动参数，不必重新导入已有数据。
2. **不要在运行中复制或覆盖数据库**；仅复制在线主库不是一致备份，不得混用不同数据库的 WAL/SHM。物理备份、迁移或恢复前，源与目标实例都须停止。
3. 本版无 schema 迁移；已有兼容内核无需重装。发布不会自动替换正在运行的程序，部署需单独执行。
