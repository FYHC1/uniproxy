# UniProxy 0.2.6

## 更新内容

### 现代 VLESS/VMess 协议兼容

- 修复新版 VLESS/VMess URI 被旧版严格白名单拒绝的问题，新增 VLESS XHTTP（含 Xray `extra`、`downloadSettings`、`xmux`、reuse/download 选项与 camelCase 到 kebab-case 映射）、HTTPUpgrade、VMess KCP/mKCP、ECH、`vcn`/`pcs`、VLESS Encryption 与 `raw`/`tcp`、`websocket` 等现代别名解析。
- HTTPUpgrade 按固定内核语义映射为 `network: ws` + `ws-opts.v2ray-http-upgrade: true`，不写不存在的 transport 名；VMess KCP 使用 `kcp-opts`；ECH 使用 `ech-opts`；VLESS Encryption 在严格格式校验后保留在 `encryption`。
- VMess JSON 支持 v2rayN 的 `net=raw/kcp/httpupgrade` 与 `insecure` 字段；VMess XHTTP 因固定 VMess 适配器没有 XHTTP 选项而明确报错，不静默降级。
- 明确拒绝无固定内核等价字段：Reality `spx`（非空且非 `/`）、`pqv`、`fm`、`flow=xtls-rprx-vision-udp443`、XHTTP `noSSEHeader`、`scMaxBufferedPosts`、`scStreamUpServerSecs`、`serverMaxHeaderBytes`、`h2Params`。无法精确映射时返回来源错误，不伪装成成功或丢失 TLS/证书校验。
- 固定 Mihomo 仍为 v1.19.32；`mihomo -t` 不校验 transport 名称，未知 network 会走默认 TCP，因此实现按固定内核源码分支映射，并用 native map 单测覆盖。解析成功不等于真实远端节点连通。

## 兼容范围

- 无数据库 schema 迁移；不改 API、节点身份、中转依赖、策略组、系统代理或防火墙设置；Mihomo 仍固定 v1.19.32。
- 现代协议只覆盖固定内核可证明的等价字段。VMess XHTTP、Reality `spx`/`pqv`/`fm`、`flow=xtls-rprx-vision-udp443` 及部分 XHTTP 无等价字段仍会被明确拒绝，不会静默降级为 TCP。
- `mihomo -t` 只能证明配置语法可被核心读取，无法证明 transport 实际工作或远端节点可连接；真实连通性、延迟与吞吐取决于节点、网络和内核环境。

## 升级与数据安全

1. **先退出旧 UniProxy 实例并确认其内核退出，再替换主程序**。沿用原数据目录、匹配主密钥和启动参数，不必重新导入已有数据。
2. **不要在运行中复制或覆盖数据库**；仅复制在线主库不是一致备份，不得混用不同数据库的 WAL/SHM。物理备份、迁移或恢复前，源与目标实例都须停止。
3. 本版无 schema 迁移；已有兼容内核无需重装。发布不会自动替换正在运行的程序，部署需单独执行。
