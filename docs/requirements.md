# UniProxy 需求基线

更新：2026-10-20（Asia/Shanghai）。这是已经讨论的产品需求与当前实现边界，不是未经批准的新功能清单。

入口：[文档索引](<README.md>) · [开发计划](<development-plan.md>) · [接续快照](<session-handoff.md>)。

## 1. 使用场景和部署

- 个人浏览器、工具代理，同时服务爬虫和自动化程序。
- Windows 本机、Linux 服务器、Docker；预期管理数百个节点。
- 单管理员 Web 管理界面 + API，不做多租户。
- “出口端口”指客户端连接 UniProxy 的本地/服务端代理入口，不等同于固定公网出口 IP。
- “格式转换”包括配置标准化和内核实际协议转接；只有导入成功不能宣称节点能联网。

## 3. 必须保留的行为边界

### 代理和调度

- 内核当前固定 Mihomo v1.19.32，Go 编写。不是 PyPI 同名 Python 数据客户端。
- 轮询按新连接/内核流调度，不是每个 HTTP 请求必换 IP；连接复用保持原出口。
- 原生粘性缓存约 10 分钟，有限容量，可能因淘汰、重载、重启或节点变化失效。
- in-user 是预先配置的代理用户名，不是任意动态 session-ID；管理员 Token 与代理凭据分离。
- 空池、失效目标、中转缺失/禁用均禁止直连回退；未知健康不等于已坏。

### UDP 是安全受限的支持

用户要求第一版 UDP，后续源码核对发现固定内核 UDP 不检查用户名/密码、也无 InUser；实现因此限制为回环地址。此限制是明确的工程安全边界，不可写成“已经支持公网认证 UDP”。若未来需要 LAN/公网 UDP，须另行设计、确认并测试，不能删掉校验来满足表面功能。

- mixed/socks 才能开启 UDP；HTTP 入口不能开启。
- UDP 入口不能绑定 in-user 池，UDP 池只选择兼容节点。
- 同机其他进程仍可向回环 UDP 发包。
- Docker bridge 方案提供对宿主的认证 TCP；Linux host 网络可使用回环 UDP。Windows 本机 UDP 推荐原生运行。

### 导入和同步

- 解析离线、无网络/文件/执行副作用；不会自动采用源文件的监听、控制器、rules、DIRECT 或外部 provider。
- 同文件具体节点中转链最多 16 条依赖边；目前不支持 dialer-proxy 引用策略组，也不支持 sing-box detour。
- 中转依赖校验失败应报错，不能忽略字段并改成直连。
- 128 是错误详情上限，不是总错误上限；扫描要继续，TotalErrors/ErrorsTruncated 真实反映结果。
- 删除独享目标自动停用入口并保留配置，端口不静默换绑；中转删除保留阻断依赖及恢复所需身份。

## 4. 安全和非功能需求

- 默认回环监听；非回环管理需至少 24 字节 Token，代理 TCP 入口需认证，公网管理另配 HTTPS。
- 不输出节点密码、私钥、完整订阅令牌、数据库主密钥；明文导出必须明确确认。
- SQLite 的配置快照加密不等于全盘加密；密钥和数据库同机，活动记录另表。进程内存仍含运行必需凭据。
- 保存配置不代表正在代理；UI/API 必须展示 running/dirty/appliedRevision/lastError。
- 不改系统代理、防火墙或用户网络设置；测试和开发使用隔离数据。
- 跨平台交叉编译不等于跨平台实跑；配置校验不等于公网可用；测试 fixture 不得出现在生产初始数据。
