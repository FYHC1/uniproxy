# UniProxy 第一版架构

## 已确认范围

- 单管理员 Web + REST API，Windows / Linux / Docker，面向数百代理节点。
- 上游 VLESS、VMess、Trojan、Shadowsocks、Hysteria/Hysteria2、TUIC、SSH、SOCKS5、HTTP(S)。
- 下游 HTTP-only、SOCKS5-only、mixed，同一 mixed 端口兼容 HTTP 与 SOCKS5；SOCKS5 UDP 纳入第一版。
- 独享入口绑定单节点；共享入口绑定代理池。池策略 URL Test、轮询、一致性哈希、内核原生粘性会话。
- 节点多分组；池静态节点 + 分组任一/全部 + 排除规则。订阅完整成功刷新时自动清理已移除的来源节点。
- 修改校验后自动应用，失败明确显示运行版本与待应用版本；高影响操作提示。

## 控制面与转发面

UniProxy（Go）负责节点/分组/订阅/入口/代理池/异步检测任务。React 仅与同源 UniProxy API 通信。编译后的前端嵌入 Go 可执行文件。SQLite 以 AES-256-GCM 加密配置快照，独立本地 master.key；日志与活动保留有限条目。

数据库仅state配置payload加密，活动记录/表结构不是SQLCipher式全文件加密；备份需数据库与匹配密钥，在线WAL不能只复制主db。

Mihomo 独立进程负责协议转接与 TCP/UDP 流量。管理 API 不转发普通业务流量，不为每个节点创建额外进程。控制器和测速探针仅使用随机端口的认证回环入口；不将内核 API 直接暴露给浏览器。

首版固定经过兼容性验证的 Mihomo v1.19.32。不会自动下载并执行任意远程脚本，也不静默升级内核。

## 内置内核安装生命周期

缺失内核不阻止管理服务启动。管理器统一检测显式路径、平台数据目录/core、旧 bin、程序同目录与 PATH；WebUI 首次缺失提示和运行/设置入口调用同源已鉴权安装 API。固定版本下载逻辑在[内部模块](<../internal/coreinstall/install.go>)，不再依赖独立安装器进程。

安装预约排斥启动/应用，后台下载不占配置互斥；状态在内存，Bootstrap 和专用 GET 报告真实阶段/字节、目标路径和错误。先验证官方发布与内置摘要，再安全解压，使用同目录硬链接做原子无覆盖发布。不会升级或覆盖已有文件；关闭服务取消并等待清理。安装后只做版本检测，不应用配置；管理员必须显式 Apply，当前进程内包括订阅刷新在内的配置变更不会趁机启动代理。状态不写入备份和 DB schema。

## 数据模型

- Node：稳定ID、标准协议配置、来源引用、人工/来源分组、启用/检测状态，及DialerID稳定依赖、DialerIdentity上游身份墓碑；后者不对普通API列表公开。
- Group：独立 ID、名称、颜色；节点多对多关系。
- Subscription：URL、分组、刷新间隔、错误状态。UI 隐藏敏感 URL 路径/query。
- Pool：策略、hashKey、静态成员、分组匹配模式、排除成员、UDP、独立 URL 检测设置。
- Listener：监听地址、端口、mixed/http/socks、绑定节点/池、UDP 开关、代理认证列表。
- Settings：全局检测 URL、下载测速目标、并发、超时、流量上限、端口分配范围。
- Runtime：内核版本、运行状态、应用版本、实际监听状态、错误；与数据库配置版本分离。

## 选路语义

不添加 DIRECT 兜底。所有入口显式绑定目标，空池和过期目标拒绝；全局最终规则 REJECT。未知健康状态不直接视为失败，池内健康判定交由内核。

轮询单位是连接/内核流，而非每个 HTTP 业务请求；Keep-Alive 和 HTTP/2 会复用原连接。一致性哈希默认使用目标地址。粘性会话默认来源+目标，使用内核缓存（10 分钟，有限容量，可被淘汰）。支持 hash-key=in-user 的池必须在每个接入入口配置认证；用户名是已注册的代理访问凭据，不是任意动态 Session ID。

组顺序/节点标签由稳定 ID 生成，界面改名/排序不会改动选路标签。成员新增、删除、故障、重载或进程重启仍可能改变映射。粘性不承诺跨重启或跨配置重载持久化。独享节点也不保证其上游运营方永久固定公网 IP。

## UDP

HTTP 和 SSH 上游不具备原生 UDP 能力。启用 UDP 的池仅选择 UDP-capable 节点；UDP 入口不能绑定未开启 UDP 的池。mixed 与 socks 的 UDP 关联仍有 TCP 控制连接；客户端必须支持 SOCKS5 UDP ASSOCIATE。浏览器通过 HTTP CONNECT 不等于使用 SOCKS5 UDP。

安全限制：固定版本 Mihomo 的原生 SOCKS UDP 处理不执行用户名/密码认证，也不携带 InUser。第一版仅允许回环 IP 的 UDP 监听，并拒绝 UDP 入口绑定 hash-key=in-user 代理池。即使 TCP 有认证，不能将 UDP 对外监听视为安全。

Docker bridge 模式第一版提供对外认证 TCP 入口，不能直接向宿主映射本机回环 UDP。Linux 需要本机 UDP 时可用 host 网络并绑定127.0.0.1；Windows建议原生运行。未实现经过认证的公网 UDP 网关，不能通过关闭校验绕过限制。端口范围外创建的入口不能自动出现在宿主机。

## 配置生命周期

1. 复制当前状态，执行一个逻辑批次的变更，验证引用、端口、权限和字段范围。
2. 编译并用内核校验候选配置（尚未安装内核时允许保存，并明确提示未生效）。
3. SQLite 原子保存新期望版本。
4. 运行内核 reload/启动并验证实际入口；成功更新运行版本。
5. 失败保留待应用版本及清晰错误，尽可能保留/恢复上一份运行配置。回滚本身失败时不能伪装成功。

正常更新不主动调用删除连接接口，不为普通编辑重启内核。禁用/删除节点阻止后续新连接；已建立 TCP 尽量自然结束。重载可能重置原生 UDP 映射和粘性缓存，改端口/认证可能重建监听；升级、停止、故障恢复重启会断开连接。不承诺严格全协议零中断。

## 订阅一致性

依据去除显示名称后的完整连接配置指纹去重，而非仅地址/端口。一个节点可被多个订阅或人工导入引用。同文件Clash dialer-proxy先解析成有向无环依赖，再用上游递归指纹参与下游身份计算；别名去重后使用稳定DialerID，显示名变化不影响链路。中转配置/凭据变化则改变依赖链指纹。

链深度最多16；引用只在同一文件解析，策略组/内置策略/缺失/重复名称/循环引用明确拒绝。删除或禁用中转后，其下游仍保留依赖ID但不参与转发或代理池；不能通过移除dialer-proxy回落直连。备份与节点YAML导出保留依赖，重复显示名导出时使用无冲突稳定标签。

成功完整刷新仅替换本订阅的引用与来源分组，保留人工名称、启禁、人工分组；消失引用清理后，只删除无来源且非人工保留的节点。删除节点移除池静态引用，并停用保留独享入口，避免端口静默转给另一个节点。

网络错误、HTML 登录页、部分解析失败不执行清理。空源或超过50%删除须用户显式确认强制刷新（强制也不能绕过解析错误）。

## 安全和明确限制

默认回环管理入口。非回环管理必须24字节以上管理员 Token；非回环代理入口必须用户名/密码。公开部署应通过 HTTPS 反代访问管理界面；普通 SOCKS5/HTTP 认证本身不是加密传输。

订阅默认屏蔽内网/回环/保留地址，DNS 解析后地址校验并固定拨号，重定向重新校验。显式环境开关可允许受信任内网源。导入不能指定本地文件、执行脚本或注入内核全局路由。

数据库加密不等于整机防护：master.key、内核进程内存和导出备份均敏感。内核候选/运行配置通过stdin和认证回环API传入，不持久化明文YAML；内核环境剔除CLASH_*/MIHOMO_*覆盖以避免继承的监听或post-up配置绕过平台。Unix目录0700/密钥文件0600，Windows需要保护账户与目录ACL。备份导出为明文，UI明确警告。

首版无分布式、多租户、TUN、计费、定时下载测速、任意动态会话账户。
