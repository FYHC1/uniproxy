# Clash中转、拖拽导入与分组筛选修复

## 原因

旧版本在配置解析时把dialer-proxy当作禁止的委托字段，并在记录128条错误后停止扫描。该错误不是连通性检测，更不能据此判断GFW屏蔽。移除dialer-proxy会把本应中转的节点变成直接拨号，因此不能用忽略字段方式“修复”。

## 实现

- 两遍解析同一Clash文件的具体代理节点名，允许前向引用。中转链校验缺失/无效/重名/自身/循环/超过16层；引用策略组或内置DIRECT等明确拒绝，不私自简化策略。
- 本次文件引用的是具体中转节点，不需要导入源文件的proxy-groups、全局rules、端口或controller。只导入节点和安全的节点依赖。
- 依赖先使用上游递归配置指纹去重，再映射成内部稳定节点ID。中转别名合并仍保留正确依赖，修改显示名不影响连线；上游凭据变化改变链身份。
- 中转禁用/删除后，下游不参与池、不接受新流量、不直连回退。公开列表显示关联中转与错误原因。原有TCP自然结束语义不变。
- 备份/导出保留链，导出避免保留字和名称碰撞；删除中转后的身份墓碑允许备份恢复再导入原文件时修复原节点ID，不遗留旧监听。
- 详细错误仍最多128条，但总数完整统计，继续处理后续有效节点；UI明确提示截断。
- 本地导入支持拖入/点击选择单个<=5MiB文件。拒绝多文件/目录，拖放不跳转浏览器，读取/预览结果有版本防串用。
- 分组过滤支持包含任一/全部、排除任意所选分组、仅未分组。排除优先；仅未分组清空并禁用包含条件。只筛选显示，不删除/改组；已选但被筛掉的节点仍提示。

## 指定文件离线验收

只读取用户明确指定的源文件到内存，不复制凭据进仓库/日志，不连接文件中的远端节点，不修改现有数据：

- 328个节点定义全部解析；178个带同文件中转依赖。
- 3个中转别名与普通节点连接配置相同，去重后325个节点。
- 隔离临时SQLite导入/重复导入后ID稳定，无新增重复，178个依赖都指向有效节点。
- 生成配置经过实际Mihomo v1.19.32校验通过。
- 这不是远端连通/测速结果，未验证GFW状态。

## 自动化

- 图解析：前向/别名/错误/长链/循环/错误数量截断，直接节点老指纹兼容。
- 真实本机两跳SOCKS代理链已通过，验证中转与出口都实际经过；中转禁用不绕过，重新启用恢复。
- API：多来源刷新、图身份变化、预览无副作用、YAML/备份往返、保留字/缺失依赖名碰撞、删除-编辑-备份-恢复-重导入保持ID。
- 浏览器真实隔离API的7项测试已通过：拖放Clash后预览链并导入、排除组保留未分组、仅未分组/清空重置，以及原5项CRUD回归。
- 前端synthetic测试额外覆盖目录/多文件/大小、迟到读取/预览、过滤任一/全部/排除/翻页与隐藏选择；21项工具单元测试及严格TypeScript检查通过。
- 全量Go测试（含原文件离线测试、真实本机中转链）与go vet通过；更新版exe隔离启动/CLI验证通过。

## 升级不动现有数据

用户当前运行中的bin/uniproxy.exe没有被强制停止，也没有替它写入导入数据。新版构建在bin/updates/uniproxy.exe，需退出旧进程后替换原exe并在原工作目录重新启动；**不要删除bin/data或改用新数据目录**。前端嵌入exe，重启后浏览器刷新才会看到变更。重新导入原文件会按配置去重补齐节点，不必删掉之前成功导入的节点。内核二进制版本未变。
